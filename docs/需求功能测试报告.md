# 需求功能测试报告

测试日期：2026-06-29  
需求来源：`docs/需求.pdf`  
项目范围：学生微信小程序 `miniprogram-1/`、辅导员/管理员网页端 `web-counselor/`、后端 `demo/`

## 1. 测试结论

项目已经覆盖需求中的主要业务主线：学生端知识库/AI 咨询、模板下载、党团进度与思想汇报、通知接收与反馈、电子证明申请、请假审批、学业分析、学生管理、通知发布和后台审批管理均有页面与接口实现。

但不能判定为“全部完成”。当前仍有以下明显缺口：

- 后端完整自动化测试未通过：111 个测试中 3 个失败、15 个错误。
- “理论自测”在需求中标为可选，但当前未发现题库导入/答题/成绩记录页面或接口。
- “多渠道通知”的小程序站内消息已实现，邮件/短信批量发送未发现实际发送实现。
- “电子证明自动生成 PDF 预览”未完成，目前是申请和审批流，未发现证明 PDF 生成/下载接口。
- “成绩单 PDF 上传解析”未完成，目前学业分析支持手动录入和文本批量导入课程，培养方案 PDF/JSON 可解析，但学生成绩单 PDF 上传解析未发现入口。
- 后端通知反馈/AI 上下文相关测试存在外键清理错误，学生画像筛选 mapper 测试断言失败，需要修复后再作为验收依据。

综合判断：核心演示功能约为“基本完成到部分增强完成”，适合继续做联调演示；若按需求逐条验收，应先补齐上述缺口并修复后端测试。

## 4. 建议的手工验收流程

### 4.1 启动环境

1. 启动后端：
   ```bash
   cd demo
   bash ./mvnw spring-boot:run -Dspring-boot.run.profiles=h2
   ```
2. 启动管理端：
   ```bash
   cd web-counselor
   npm run dev
   ```
3. 微信开发者工具导入 `miniprogram-1/`，关闭域名校验，确认 `miniprogram-1/utils/config.js` 的 `BASE_URL` 指向后端地址。

### 4.2 登录账号

- 学生端：`2023001 / password`
- 学生骨干：`2023003 / password`
- 辅导员网页端：`10000001 / counselor123`
- 管理员网页端：`admin / admin123`

### 4.3 知识库、AI 咨询、模板下载

操作位置：

- 管理端：左侧菜单“知识库”
- 小程序：首页“政策知识库”或服务页“政策知识库”
- 小程序：首页右下角“AI”

测试步骤：

1. 管理端进入“知识库”，新增或确认已有知识文章，上传资料文件，设置分类、标签、适用年级/专业。
2. 小程序学生登录，进入“知识库”，输入关键词搜索，例如“入党申请书”。
3. 打开文章详情，点击“下载/打开资料”。
4. 返回首页点击“AI”，提问“入党申请书怎么写”或“请假怎么办”。

预期结果：

- 搜索结果能返回相关知识条目。
- 文章详情能展示标题、摘要、适用对象、资料说明。
- 开发者工具中 CSV/TXT 类文件能在 Console 打印内容；真机应调用文档预览。
- AI 回复应带知识/通知引用或自动降级到知识检索结果。

### 4.4 党团事务流程

操作位置：

- 小程序：服务页“党团进度”“思想汇报”“党团活动申请”
- 管理端：左侧菜单“党团管理”

测试步骤：

1. 学生进入“党团进度”，查看当前阶段、流程节点和提醒。
2. 学生进入“思想汇报”，选择 PDF/Word 附件并提交。
3. 学生进入“党团活动申请”，填写标题、事由并提交。
4. 辅导员登录管理端，进入“党团管理”，查看思想汇报和党团活动审批列表。
5. 对申请执行通过/驳回。

预期结果：

- 学生能看到当前党团阶段和待办提醒。
- 思想汇报仅允许 PDF/Word。
- 管理端能看到待审批记录并完成审批。
- 学生端再次查看时状态应更新。

未覆盖项：

- 理论自测未发现入口，无法按需求验收。

### 4.5 信息推送与反馈

操作位置：

- 管理端：左侧菜单“通知发布”“反馈处理”
- 小程序：底部 Tab“通知”、通知详情页
- 学生骨干小程序：待处理反馈页

测试步骤：

1. 管理端进入“通知发布”，新建通知，填写标题、正文、标签和发布范围。
2. 使用“预估发布人数”检查目标范围。
3. 点击“发布”。
4. 学生端进入“通知”，打开通知详情，提交疑问反馈。
5. 学生骨干进入“待处理反馈”处理或上报。
6. 辅导员管理端进入“反馈处理”查看处理链路。

预期结果：

- 通知能按筛选范围投递到目标学生。
- 学生端能查看通知、标记已读、置顶/取消置顶、提交反馈。
- 骨干/辅导员能处理反馈并留下处理记录。

风险点：

- 后端通知反馈测试当前受外键约束失败，需要修复测试数据清理。
- 邮件/短信发送未发现实现。

### 4.6 电子证明申请与审批

操作位置：

- 小程序：服务页“电子证明生成”
- 管理端：左侧菜单“证明审批”

测试步骤：

1. 学生进入“电子证明生成”，点击“申请证明”。
2. 选择证明类型，填写标题和理由并提交。
3. 管理端进入“证明审批”，打开申请详情。
4. 点击“通过”或“驳回”，驳回时填写原因。
5. 学生端刷新证明列表查看状态。

预期结果：

- 申请能进入待审批列表。
- 管理端能审批通过或驳回。
- 学生端状态同步为已通过或已驳回。

未完成项：

- 未发现自动套模板生成证明 PDF、PDF 预览和下载能力。

### 4.7 学业分析与预警

操作位置：

- 小程序：服务页“学业分析与预警”

测试步骤：

1. 学生进入“学业分析与预警”。
2. 手动添加课程，例如“程序设计”，填写学分或选择自动识别。
3. 使用“批量导入”，粘贴多行课程：
   ```text
   程序设计,专业模块,3
   高等数学Ⅰ,通识模块,4
   ```
4. 查看各模块已修/剩余学分。
5. 点击模块查看未修课程和推荐课程。

预期结果：

- 课程能保存并参与统计。
- 页面展示培养方案模块、剩余学分、未识别课程和未修课程。
- 推荐课程按缺失模块和培养方案课程池返回。

未完成项：

- 未发现成绩单 PDF 上传解析入口。

### 4.8 学生管理与账号导入

操作位置：

- 管理端：左侧菜单“学生管理”

测试步骤：

1. 辅导员/管理员进入“学生管理”。
2. 点击“导入学生”，下载 CSV 模板。
3. 使用模板填写学生数据后上传。
4. 查询学生列表，按年级、专业、身份筛选。
5. 使用新导入学生账号登录小程序。

预期结果：

- CSV 模板能下载。
- 单个导入和批量导入能创建学生/学生骨干账号。
- 学号为纯数字，学生身份/年级按 `2023本`、`2022硕` 等格式展示。

风险点：

- `StudentProfileMapperTest` 当前目标学生筛选失败，精准推送相关筛选需要重点回归。

## 5. 建议修复优先级

1. 修复后端测试：先处理 `AiContextServiceTest`、`NoticeFeedbackServiceImplTest` 的外键清理顺序，再处理 `StudentProfileMapperTest` 的筛选 SQL/测试数据。
2. 补齐电子证明 PDF 生成：审批通过后生成 PDF 文件，学生端提供预览/下载。
3. 补齐成绩单 PDF 上传解析：学生端上传 PDF，后端解析课程/成绩并写入学业分析记录。
4. 决定是否实现理论自测：如果作为可选项不做，应在验收说明中明确标注“可选未实现”。
5. 决定邮件/短信是否纳入本期：如果只做站内消息，应调整需求说明或验收口径。
6. 做一次真实端到端联调：用 H2 或 PostgreSQL 启动后端，管理端发布通知/知识/审批，小程序端完整走学生流程。
